# История справочника товаров на SQLite

[← Каталог моих проектов](https://github.com/Decl1s/Decl1s/blob/main/PROJECTS.md) · [С чего я начинаю](NOTES.md) · [Контракт и решения](CONCEPT.md) · [Что я проверил](VALIDATION.md)

Я сравниваю состояние товара на две даты и объясняю, почему прежняя цена остаётся в истории.

Я разработал этот учебный проект 16 октября 2026 года, чтобы изучить историю изменений на SQLite. Полные CSV-снимки справочника
превращаются в историю **SCD Type 2**: старая цена не теряется после обновления.
Новый инструмент серии — SQLite, SQL и транзакции. Все примеры синтетические.

## Запуск за пять минут

Нужен Python 3.11 или 3.12 со встроенной SQLite **не ниже 3.37**. Сторонних пакетов нет.
В каталоге проекта создайте окружение:

```sh
python -m venv --without-pip .venv
```

Linux: `source .venv/bin/activate`. Windows PowerShell: `.venv\Scripts\Activate.ps1`.
Если активация недоступна, используйте `.venv/bin/python` на Linux или
`.venv\Scripts\python.exe` на Windows вместо `python` во всех командах.

```sh
python -m catalog_history demo
python -m catalog_history load
python -m catalog_history as-of 2026-10-04
python -m catalog_history as-of 2026-10-05
python -m catalog_history as-of 2026-10-10
```

Демо создаёт три CSV и 12 строк наблюдений. Первая загрузка даёт **9 версий, 5 актуальных
товаров, 4 закрытия версий, 3 изменения атрибутов и 1 исчезновение**.
Цена чая меняется с 250,00 до 275,00 ₽ начиная с 5 октября. Блокнот отсутствует
с 5 по 9 октября включительно и возвращается 10 октября с ценой 210,00 ₽.

Состояние сохраняется в `workspace/catalog.sqlite3`, входы — в `workspace/input/`.
Приложение не создаёт сервер, фоновый процесс или сетевые подключения.

## Контракт данных

**Каждый файл — полный справочник, а не список изменений.** Отсутствующий товар
закрывается на дату снимка. Пустой снимок с одним заголовком закрывает все товары.
Не передавайте сюда неполную выгрузку или случайно обрезанный файл.

Имя: `catalog-YYYY-MM-DD.csv`; дата — календарный день начала действия полного снимка.
Кодировка UTF-8, допустим BOM; разделитель — запятая; заголовок строго такой:

```csv
product_id,name,category,price_cents
P-0001,Чай,Напитки,25000
```

| Поле | Правило |
| --- | --- |
| product_id | P- и 4 ASCII-цифры; один код встречается в снимке ровно один раз |
| name, category | От 1 до 80 символов, без крайних пробелов и управляющих символов |
| price_cents | Целое число копеек от 0 до 100 000 000; без знака, дроби и ведущих нулей |

Неверная строка отклоняет **весь запуск**. Карантин отдельных строк здесь опасен:
исключённая строка выглядела бы как исчезнувший товар.

## Что находится в базе

- `batches`: дата, SHA-256 исходных байтов и число товаров в принятом снимке.
- `dim_product`: отдельный ключ версии, код товара, атрибуты, `valid_from` и `valid_to`.
- `current_products`: представление открытых версий.

Интервал действия — `[valid_from, valid_to)`: начало включено, конец исключён.
`NULL` в `valid_to` означает открытую версию. Частичный уникальный индекс запрещает
две открытые версии одного товара. Запрос на дату хранится в `catalog_history/sql/as_of.sql`.

Для просмотра через Python:

```python
import sqlite3
from contextlib import closing

with closing(sqlite3.connect("workspace/catalog.sqlite3")) as db:
    print(db.execute("SELECT product_id, price_cents, valid_from, valid_to "
                     "FROM dim_product ORDER BY product_id, valid_from").fetchall())
```

## Повторы и сбои

Дата уже есть и SHA-256 совпадает — снимок пропускается. Изменились даже только переводы
строк загруженного файла — отказ. Новый снимок раньше последней принятой даты также
отклоняется: исправление прошлого требует отдельного механизма пересборки.
Удаление старого входного CSV не удаляет уже принятую историю.

Все новые снимки одного запуска обрабатываются внутри одной `BEGIN IMMEDIATE`
транзакции. При обычном сбое откатываются версии и контрольные точки всего нового
пакета. После сбоя первой загрузки может остаться пустая схема проекта; её можно
повторно использовать. Пустой чужой файл базы автоматически не присваивается проекту.

## Ограничения и приватность

До 30 CSV за запуск, 10 000 товаров на снимок, 2 МиБ на файл, 32 МиБ суммарно;
существующая база не больше 256 МиБ. Входы целиком читаются в память.
История по дням, без нескольких изменений в течение дня и без знания времени получения.
Снимок считается действующим до следующего снимка. Запись предполагает одного
запускающего; при блокировке SQLite ожидает до 5 секунд и может вернуть ошибку.
Скорость на больших данных, авария питания и одновременное изменение входов не проверялись.

Не меняйте CSV во время загрузки: сохраняются хэши прочитанных байтов, а согласованность
снимков разных файлов с внешним источником проект не обеспечивает.
База узнаётся по метке приложения и версии схемы; её ручное изменение не поддерживается.
Чужая база, символические ссылки и расположение базы внутри входной папки отклоняются.

Генератор не читает документы, профиль или окружение пользователя. В Git и исходный ZIP
попадают только файлы из `PUBLIC_FILES.txt`; входы, базы, история Git и окружение исключены.
Проверка ищет контакты, типичные секреты, локальные пути и лишние отслеживаемые файлы.
Метаданные авторства публичных коммитов GitHub видны посетителям репозитория;
адреса вне домена no-reply вызывают примечание без вывода самого адреса.
Контакты в содержимом исходников по-прежнему запрещены. Это вспомогательная проверка,
а не полный аудит произвольных будущих изменений. Настоящие рабочие справочники не публикуйте.
